# モーションサイジング

VRMA、BVH、FBX、Unity Humanoid `.anim` を読み込んだ後のAvaAvaDanceのキーに、体格差・移動量・接触位置の補正を適用します。Unityのメイン画面内で操作でき、別アプリやWin32の拡張ウィンドウを起動する必要はありません。

## 操作

1. モデルにモーションを読み込みます。すでに `.avadance` を開いている場合や `.avamotion` を読み込んだ場合も、そのまま使えます。
2. MikuMikuDance風の画面では「編集 → モーションサイジング」、MikuMikuMoving風の画面ではリボン「編集 → モーションサイジング」を選びます。
3. 「モーションのあるモデル」と「適用先モデル」を選びます。どちらも現在のモデルが初期値です。別の体格へ移す場合は、両方のモデルをシーンに読み込んで適用先を変えます。
4. 開始・終了フレームを指定します。「全フレーム」は元モデルのベースキー全体、「選択範囲」は元モデルで選択したベースキーの最初～最後です。
5. 必要な補正を選び、「サイジング実行」を押します。計算中は中止できます。結果は適用先モデルの通常のキーとして反映されます。
6. 通常のUndo／Redoでまとめて取り消し・やり直しできます。モーションは `.avamotion`、シーン全体は `.avadance` へ保存します。

## モーション元モデルの意味

ここでの元モデルは、**現在の内部キーが属しているモデル**です。VRMA・BVH・FBX・animの読み込み時点で、腰移動と回転軸はそのモデルへ変換されています。元ファイルの身長倍率を再適用しません。

同じモデルを元と先に選んだ場合、体格比は1です。移動倍率や接触位置の調整に使えます。別モデルを選んだ場合は、元モデルと先モデルの編集用基準姿勢・脚の長さから変換します。元ファイルや元ファイルを制作した環境は必要ありません。特にHumanoid `.anim` は制作元の体格情報を含むとは限らないため、読み込み後のモデルを基準にします。

## 設定

| 設定 | 内容 |
| --- | --- |
| 移動倍率（XZ） | 水平方向の移動量。1は体格比どおり、0は水平移動を止める設定です。上下移動は体格比を使います。 |
| 足・つま先の位置を合わせる | 元の足の位置・床からの高さを参考に、脚の回転を解いて補正します。Humanoid読み込みで足IKがOFFでも動作します。 |
| 足幅補正（片足・m） | 各足を左右へずらす量。正の値は足幅を広げます。 |
| 床の高さ（m） | 足位置補正で使う床の高さ。 |
| 手首の位置合わせ | 元で近づいている左右の手首の接触位置を、先モデルでも保つように腕を補正します。 |
| 指先の位置合わせ | 対応する指先がある場合に、指先の接触位置を使って補正します。 |
| 身体との接触回避 | リグのコライダーなどを使って、腕・手が身体へ入り込む箇所を補正します。 |
| 腕・手首の捩り分散 | 対応する捩りボーンがあるリグで、腕・手首の回転を分散します。 |
| 接触判定距離（m） | 手首・指先を接触しているとみなす距離。 |
| 表情対応 | `元の表情名:先の表情名:倍率`。複数の指定は`;`で区切ります。例：`笑い:Smile:1;まばたき:Blink:0.8`。 |
| カメラも体格に合わせる | シーンのカメラキーを、選んだモデルの表示上の体格差と移動に合わせます。モデル以外の被写体がある場合は結果を確認してください。 |

脚の対応トラックがない場合や、脚の長さで届かない接地点がある場合は処理結果に記録します。腕などもモデルの構造によって補正できる範囲が変わるため、適用後にプレビューで確認し、必要なら通常のキー編集で調整してください。

## キー・レイヤーの扱い

対象はベースキーです。レイヤーとクリップは保持し、合成済みの動きをベースへ二重に焼き込みません。別モデルへ適用するときも、先モデルにあるレイヤーは残ります。

補正するフレーム範囲には必要なボーンキーを生成します。途中の範囲を補正する場合は、境界に元の動きを復元するキーを補います。全フレームを処理した場合は補正後の最終姿勢を維持します。補間を含む元キーを直接VMDへ変換しないため、長いUnicode名・同名ボーン・物理OFFフラグを扱えます。変更しないトラックの値やメタデータは維持します。

単純な同一モデルの移動量変更では元の補間を使います。FK補正や回転した座標系での複数軸の混合などが必要なトラックは、30 fpsの整数フレームへ結果を焼き込み、新しい補正キー間を線形で補間します。接触回避はリグのコライダーを使う幾何学的な補正です。

## 実装

- `Assets/AvaAvaDance/MotionSizing/`：Unityがビルドに組み込むC#の補正計算。`Ava.MotionSizing`アセンブリはUnityオブジェクトに触れず、`MotionSnapshot`・`RigProfile`から`KeyEdit[]`を作ります。
- `Runtime/MotionSizingUI.cs`：Unity UI Toolkitの設定画面。メインスレッドで取得した複製から計算し、完了後に`ApplyMotionChanges`を一回呼びます。
- `TrackSnapshot.RigJointIndex`：表示名に依存しない、実際のボーンとリグ配列の対応。視線・論理コントロールなどの追加より前にTransformとの対応を保存します。
- 内部ボーン変位の単位はUnityのローカル座標です。リグは`editRest`を優先し、プレビュー表示用の縮尺を混ぜません。
- カメラ補正には、モデル読込時に保存した編集用リグから表示シーンへの変換を使います。表示用にモデルが正規化されていても、カメラ距離や注視点を元の身長比だけで変えません。
- キー更新前に、計算に使った元モデル・先モデルとトラックRevision・プロジェクト世代を照合します。キャンセルや計算エラーではキーを部分的に反映しません。

公開機能はVMDの読込・書出しを通りません。従来のVMD参照用拡張は`developmentOnly`のまま、通常ビルドから除外します。

## 検証

Unityを必要としない補正計算の回帰テスト：

```sh
dotnet run --project Tests/MotionSizingHarness
python Tests/check_project.py
```

通常ビルドのメニュー試験`-avaMenuSmoke`は、MMD風／MMM風の両方でUnity内の画面が開き、VMD参照ツールが公開されないことを確認します。

既存の`-avaHumanoidMotionSmoke <avatar.vrm> <motion-directory>`は、VRMA・BVH・FBX・animそれぞれの読込後にサイジングを実行し、Undo／Redoと補正後の`.avamotion`保存・再読込を確認します。この試験は従来どおり所定のモーション素材とUnity／Windowsプレイヤーが必要です。
