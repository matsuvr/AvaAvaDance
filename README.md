# AvaAvaDance

VRChat アバターでモーションを作る Unity アプリの、最初の **UI 配置プロトタイプ**。
対象は **Unity 2022.3.22f1**。EditorWindow ではなく UI Toolkit のランタイム UI で、将来のスタンドアロン実行を前提としています。

## 起動

1. Unity Hub の Add project でこのリポジトリを開く。Editor は 2022.3.22f1 を指定する。
2. メニュー **AvaAvaDance > Open UI prototype** を選ぶ（または Main シーンを開いて Play）。
3. Game ビューを 1280 × 900 程度にする。狭い表示はスクロールし、パネルの並び順を維持する。
4. **Configure standalone build** を選択し、File > Build Settings で PC/Mac/Linux Standalone を選ぶと Main シーンをビルド対象にできる。対象 OS の Build Support は別途必要。

Play 時に DanceApp が UI を組み立てます。アバターや SDK は不要です。日本語は Unity/OS のフォントフォールバックに依存します。文字が欠ける環境では日本語フォントを用意して PanelSettings に設定する対応が必要です。

## 今回の範囲

- 上部メニュー、左のボーン・フレーム操作／タイムライン／補間、右の白いビューポート、下部の操作パネル。
- カメラ・照明・アクセサリとモデル操作の UI 切り替え。モデル側はボーン／表情パネルを表示。
- 前後ボタン、フレーム数入力、タイムラインクリックによる **UI 上の現在フレーム選択**。
- 未実装の操作は無効化し、ツールチップでも明示。
- 自作の床グリッド。MMD の画像、モデル、コード等は同梱していません。

**アバター読込、実際の 3D 描画／ポーズ編集、キーフレーム登録、補間編集、再生、保存、書き出し、Undo、VMD 互換は未実装です。**
モデルモードは配置確認用で、モデルが読み込まれた意味ではありません。
タイムラインにも実際のキーフレームデータはありません。

Unitypackage の Unity Editor へのインポートと、完成したスタンドアロンアプリでの読み込みは別の仕組みです。後者にはスクリプト・シェーダー・依存アセットの扱いを含む設計が必要です。今回はどちらも行わず、VRChat SDK も導入していません。

## 配置の根拠と限界

- MikuMikuDance 作者の配布ページ: https://sites.google.com/view/vpvp/
- 日本語の画面・操作資料: https://w.atwiki.jp/mmpp/pages/19.html
  - 左タイムライン、右ビューポート、下のモデル・カメラ・照明・アクセサリ・視点／再生、およびモデル選択時のボーン・表情を参照。
  - この資料は古い版です。最新版 MMD とピクセル単位で一致したという主張ではありません。

本プロトタイプは配置・区分・日本語の操作名の初期再現です。視点操作、細かな数値入力、メニューの中身などの完全一致は未達です。MMD の新しい版との実機比較で詰める必要があります。

## 検証

`python3 Tests/check_project.py` で版・構造・シーン・ランタイム/Editor 分離を検査できます。
これは Unity のコンパイルや Play 検証の代わりではありません。

作成環境に Unity Editor がなく、**Unity 2022.3.22f1 でのコンパイル、Play、ビルド、実画面比較は未実施**です。
初回レビューで以下を確認してください。

- Console にコンパイル／USS／Theme エラーがない。
- メニューから Play し、日本語の表示欠けやパネル重なりがない。
- 2 モードの切替、フレームの入力／前後／クリックが動作する。
- 未実装の読込・登録・再生・保存で操作が行われない。
- 1280 × 900 と小さなウィンドウでスクロールして全体を確認できる。
- Windows スタンドアロンにビルドして同じ UI が表示される。
